**How the background step was shortened.** The 1-hour value in the protocol is
the session token lifetime (`SESSION_TOKEN_MAX_LIFETIME`). The app stops the
core when it goes to the background and starts it again on resume
(`lib/app/lifecycle.dart`), so every resume makes a new connection and a new
token. Any time in the background takes the same path, so 20 minutes stands in
for the hour. Not covered: an app staying in the foreground past its token's
hour. The admin's app was connected 58 minutes when the Pi reboot cut it.

**Pi update details.**
- Backup first: `deploy/pi/backup.sh` → `~/vyajena-pi-backups/20261113T200810Z/`
  (2 users, keys; outside the repo).
- Downloaded at 01:32, installed at 01:38, after the temporary IPv6 test rule
  was due to remove itself (01:30). The rule was already gone (tracker note:
  firewall restored). The nftables rule set had the same hash before and after.
- Rebooted at 01:43:00. Port 8443 was back at 01:43:43, Bob reconnected at
  01:43:51 and the admin about the same time. The pin did not change.

## Findings

- **F1. A device that joins later shows no group name or display names.**
  1. The admin renames the group to "Home chat"; Bob sets display name "Bobby".
  2. Link a second device to Bob (or reset Bob and re-add him).
  3. On the new device the title is "Vyajena" and senders show as "bob" and
     "akhil", not "Bobby (bob)" (shots 18, 19, 39, 43). The older devices show
     both correctly.

  Expected (app-ui: Chat screen): every member's device shows "Ali (alice)".
  The name and profile seem to travel only as one-off messages when they change,
  so a device added afterwards never gets them.
- **F2. A removed user's devices get no notice.**
  1. The admin removes Bob.
  2. Both of Bob's devices keep the chat open and retry "Connecting…" forever,
     with no message saying he was removed (shots 34, 35).

  The spec has a notice only for removal for inactivity; a removed-by-admin
  notice, or at least an error, would be clearer.
- **F3. After a reset, the new identity keeps the old display name.** The
  warning reads "Bobby (bob)'s key changed", and the new Bob's messages show as
  "Bobby (bob)" on the admin's phone although the new install never set a name
  (shots 37, 41). It may be intended (same username); it's for the owner to decide.
- **F4. Messages from the user's other device look like someone else's.** On
  Bob's phone, "from bobs second device" is grey, on the left and has no status,
  while Bob's own phone messages are blue (shot 20). This is related to the
  own-message findings of run 1.
- **F5. Reconnect waits for the backoff after the network returns.** Airplane
  mode was turned off at 01:11:56 and the device reconnected at 01:12:25
  (~29 s). There is no reconnect on a network change.
- **F6. No chat notice for a group rename, a removal or a newly linked device.**
  The chat does not change; only the title or member count does (shots 3, 33).
  The spec doesn't require these notices.
- **F7. A Raspberry Pi kernel update doesn't create `/var/run/reboot-required`.**
  The upgrade from 6.18.34 to 6.18.60 left no marker, so `check.sh`'s
  `reboot-required` warning would not catch a pending kernel reboot.
- **Unchanged from run 1:** own messages are still full-width, left-aligned and
  labelled with the user's own name.
- **Minor:** the Pi logs `created an invite` but nothing for a revoke.

Tooling notes (not app bugs): `flutter run` on Android hung in Gradle; the
iOS Simulator dropped taps made during animations; `adb shell input text` lost
the tail of long strings unless typed in small chunks.
