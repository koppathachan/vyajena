## Why

The wire contract and its six specs exist, but nothing runs. The Pi server is the
first runnable piece and every client depends on it. The owner wants it built and
tested locally before anything else is published.

## What Changes

- **Resolve open decision #7 (build order):** pi-server-core, then the Rust core
  library, then a terminal client (the first point where two people can chat
  locally), then relay and Pi deployment, then the Flutter app with real push.
- New `server/` crate: the Pi server binary (tokio + tonic + rustls, SQLite in
  WAL mode), with one feature folder per gRPC service.
- Generated gRPC code is committed: server stubs in `server/src/pb.rs`, client
  stubs for its tests in `server/tests/support/pb.rs`, both regenerated by one
  local command and never in CI.
- `protocol/` gains the logic both the Pi and the core run: device certificate
  signature checks, device id derivation and the commit-authority rule, on plain
  Rust types (no generated code, no OpenMLS types).
- The Pi validates handshakes with OpenMLS `PublicGroup`, as the spike proved.
- Push wake pings go through a provider interface; this change ships only a
  provider that logs the content-free ping. Real FCM/APNs comes with the Flutter
  change.
- Integration tests in `server/tests/` drive a running server over real gRPC with
  OpenMLS test clients through every server-enforced spec requirement.
- No `.proto` file changes.

## Capabilities

### New Capabilities

- `pi-runtime`: how the Pi server starts and runs: configuration, first-start key
  generation, printing the TLS pin and bootstrap invite, durable storage, the
  push provider interface, and running locally.

### Modified Capabilities

Found while building tasks 4-6 and approved by the owner:

- `group-membership` (Removing a user): a removed user's username can be invited
  again, which the owner's admin-driven identity recovery needs.
- `key-directory` (KeyPackage upload): the Pi rejects KeyPackages whose
  capabilities do not list the admin group-context extension type `0xF0A1`
  (design D10), since such a device could never be added.

Every other existing requirement is implemented unchanged. `message-content` is
client-only.

## Impact

- **New code:** `server/` (binary, feature folders, committed `pb.rs`, tests),
  logic and tests in `protocol/`, the regenerate command.
- **Dependencies:** tonic 0.14, prost 0.14, tokio, rustls, rusqlite (bundled
  SQLite), openmls 0.9, ed25519-dalek, sha2.
- **Docs:** `docs/architecture-decisions.md` (decision #7 checked off), README
  ("run the server locally"), `CLAUDE.md` layout and commands.
- **Publishing:** the repo stays unpushed until this change is tested locally.
